# LUCID — Sensory Neutral Augmentative & Alternative Communication

*Perfect clarity in a loud world.*

## What this is

An offline-first AAC web app. A person taps a large, predictable button and
their own natural voice (generated by ElevenLabs) speaks instantly, with or
without internet.

## Non-negotiable product rules (from the user, verbatim intent)

- **Zero gamification**: no points, badges, avatars, rewards, streaks, confetti,
  or decorative animation.
- **Sensory neutral**: muted colors, high contrast, predictable layout, no
  flashing, no surprising motion. Prevent visual overstimulation.
- **Predictable interface**: fixed button positions; core urgent buttons are
  always visible and never reordered or removed by context.
- **Speed is vital**: minimize the time between feeling an urgent need and
  expressing it. Target < 1.5s tap-to-speech.
- **ElevenLabs is the primary voice**: natural, expressive, matching the person's
  age, accent, and personality — never a generic robotic voice.
- **Offline-first**: ElevenLabs needs internet to *generate*; the app must stay
  fully functional offline by pre-generating and caching all saved phrases.
  Must work in a store, garage, tunnel, grocery store, theater, elevator.
- **Emotion via vocabulary, not visuals**: expressing mad / urgency / happy is a
  must-have, using direct phrases, not exaggerated interface elements.
- **Context-aware vocabulary**: main screen adjusts by time/location (school,
  theater, parking lot, grocery store, restroom) but context is additive only —
  it never removes core buttons.
- **Caregiver alerts are secondary and configurable**: never block or delay the
  core tap-to-speech path; queue/skip when offline.
- **Universal by simplicity, not by options**: one simple core that adapts via
  voice profile + vocabulary set, not a settings-heavy app.

## Accessibility & contrast rules (product requirement)

- **No pure white backgrounds.** `#ffffff` is the brightest thing a screen can
  emit and a common trigger for glare, photophobia and fatigue. The canvas is a
  warm off-white (`#f4f3f0`) and tiles are `#fbfaf8`.
- **No pure black text.** Charcoal `#222222` reads the same but is less harsh
  over long use.
- **Focus / selection must never rely on a subtle colour shift.** A slightly
  darker green is invisible to many users and unusable with eye tracking. Every
  focus, hover, switch-access and tap-selection state uses a thick (4px) solid
  outline via `--focus-ring` / `--focus-width`. Selection class is `is-selected`.
- **WCAG AA minimum (4.5:1) on every text/background pairing.** Because the
  Fitzgerald palette is pastel, text inside those tiles is always dark charcoal.
- **Never rely on colour alone.** Each vocabulary category carries a distinct
  shape glyph as well as a colour, so meaning survives colour vision deficiency
  and greyscale.
- **One documented exception:** `body.high-contrast` deliberately uses pure
  white/black. For low vision the goal inverts — luminance separation beats
  glare comfort. It is opt-in and documented in the CSS.

## Colour vocabulary — Modified Fitzgerald Key (opt-in)

`body.fitzgerald` enables the standard AAC convention: yellow = people,
green = verbs, blue = adjectives, orange = nouns, purple = social words.

**Off by default.** LUCID's own principle is a sensory-neutral palette and the
Fitzgerald set is deliberately high-salience — the opposite goal. It exists for
classrooms and SLPs who already use the convention, toggled by a caregiver
(persisted as `lucid-colour` in localStorage).

Urgency always wins: `tile-urgent` / `tile-stop` keep their own colours even in
colour mode, because category must never override "a human is needed now".

Measured contrast (verified by `_lucid_verify/verify-contrast.mjs`):
people 11.29:1, verb 9.33:1, adjective 8.84:1, noun 9.62:1, social 8.21:1.
Urgent 5.58:1, STOP 7.70:1, body text 14.34:1.

## Technical architecture

- **Stack**: Node 18+ / Express (ESM), plain HTML/CSS/JS frontend (no build
  step), PWA service worker. Deploy target: **Railway** (via Nixpacks).
- **`audio/`** is the offline cache — separated from `server/` so speech survives
  server death, network loss, and browser restart. Not committed (gitignored);
  regenerated on demand.
- **`app/js/speak.js` is the single critical path** (tap → cached audio → play).
  No network call belongs there. It falls back to local speech synthesis only if
  a cached clip is missing, so the person is never left silent.
- **Atomic cache writes**: temp file → validate → rename, so a failed download
  can never replace a working clip.
- **Two-tier vocabulary**: `core/` (fixed, always visible) + context folders
  (additive only).
- **Caregiver panel** is gated behind a 2s long-press on the footer; never
  surfaced to the child by accident.

## Key files

- `server/index.js` — Express app, static + audio + API routing.
- `server/routes/api.js` — all endpoints (health, phrases, generate, prepare,
  voices, profile, alert).
- `server/services/elevenlabs.js` — TTS client.
- `server/services/cache.js` — atomic audio writes.
- `app/js/speak.js` — critical tap-to-speech path.
- `app/js/board.js` — renders core + context buttons.
- `app/js/caregiver.js` — caregiver settings panel.
- `app/sw.js` — offline service worker.
- `server/data/phrases.json` — seed phrases.
- `server/data/profiles.json` — voice/context/alert settings.

## Safety boundary

LUCID is an AAC and communication-support tool. It is **not** a medical device,
diagnostic, behavioral-treatment, or emergency-response system, and does not
replace adult supervision or emergency services. "I'M HURT"/"I NEED HELP" may
trigger a configured caregiver workflow only.
